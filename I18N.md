# Internationalization — neovibe

## Decision (2026-08-15, Charles)

Two languages coexist by design, with a clear separation of roles:

| Layer | Language | Why |
|---|---|---|
| **Configuration data** (settings.json keys/values, SSE protocol types, internal identifiers) | **English — official/canonical** | Stable across locales, matches the rest of the industry tooling (Claude Code, k8s, etc.), never translated. |
| **What the user sees** (UI labels, error messages, Neo's own conversational replies) | **User's language** | The system adapts to whoever is using it — not everyone using neovibe will be French-speaking. |

This is not "translate everything to English" (the previous pass on 2026-08-15 did exactly that
for the UI layer) — it's **the opposite direction of separation**: keep config/protocol in English
permanently, and make the *display* layer localizable instead of hardcoding it to either language.

## What already exists (English-only, correct as the base)

- `~/.neovibe/settings.local.json` keys (`api_key`) — stays English, never localized.
- SSE event types (`tool`, `step`, `token`, `error`, `done`, `heartbeat`) — protocol, stays English.
- CLI flags (`--api-key-only`, `--kubeconfig-only`) — stays English.

## What needs to change — locale-aware display

1. **`locale` setting** — new field in `~/.neovibe/settings.local.json` (e.g. `"locale": "fr"`),
   defaults to `"en"` if unset or unrecognized. Detected from `$LANG`/`$LC_ALL` at first setup,
   confirmable/overridable in the setup wizard.
2. **String table** — `bin/strings/en.json`, `bin/strings/fr.json` (extend as needed) mapping UI
   labels (`Request`, `Working`, `Response`, error messages, banner text, wizard prompts) to their
   translation. `neo_term.py`/`neo_setup.py` look up strings via `t("request")` instead of
   hardcoding English.
3. **Neo's own reply language** — currently hardcoded in the agent's system prompt
   ("Réponds toujours en français"). Should instead be driven by the same `locale` the client
   sends (e.g. as a field in the `/mission/stream` request body), so the agent answers in
   whichever language the calling user configured — not hardcoded per-deployment.

## Not in scope for this pass

- Translating `CLAUDE-*.md` / NeoKube's internal documentation (stays French — internal team docs,
  not user-facing product surface).
- A full translation of every possible locale — start with `en` (default/canonical) + `fr`
  (Charles's daily use), extend later if neovibe gets more users.

## Sequencing

Implement in this order (see Plane tickets):
1. `locale` setting + detection/wizard prompt.
2. String table + lookup mechanism, English and French.
3. Pass `locale` through to the agent so Neo's replies follow it too (backend change, not just client).
